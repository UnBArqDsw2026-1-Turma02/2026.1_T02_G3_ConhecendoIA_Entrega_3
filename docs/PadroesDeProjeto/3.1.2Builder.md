# 3.1.5 Builder

## 1. Introdução ao Padrão Builder
O padrão de projeto Builder é um padrão de criação que permite a construção de objetos complexos passo a passo. Ele possibilita a produção de diferentes tipos e representações de um objeto utilizando o mesmo código de construção.

Ao contrário de outros padrões de criação que instanciam objetos em uma única chamada de construtor, o Builder divide o processo de construção em etapas lógicas. O cliente invoca apenas os passos necessários para a configuração específica do objeto que deseja criar, tornando o processo altamente flexível e legível.

### 1.1. Problema que o Builder Resolve
Quando um objeto exige um processo de inicialização complexo, envolvendo múltiplos atributos opcionais ou coleções internas, a abordagem unconventional costuma gerar construtores gigantescos (comumente chamados de "construtores telescópicos") ou expor excessivamente os métodos modificadores (*setters*), violando o encapsulamento.

O padrão Builder resolve os seguintes problemas:
* **Construtores Polimórficos Complexos:** Elimina a necessidade de criar múltiplos construtores ou passar parâmetros nulos (`null`) para preencher propriedades opcionais.
* **Objetos Parcialmente Construídos:** Garante que o objeto final só seja disponibilizado para o sistema quando todo o seu processo de montagem estiver concluído com sucesso.
* **Imutabilidade e Encapsulamento:** Permite que o objeto final mantenha suas propriedades protegidas, concentrando a lógica de validação e montagem na classe construtora.

### 1.2. Estrutura e Participantes
O padrão Builder envolve os seguintes elementos:
* **Product (Produto):** O objeto complexo resultante do processo de construção.
* **Builder (Construtor):** A interface ou classe abstrata que especifica os passos necessários para criar as partes do objeto Produto.
* **ConcreteBuilder (Construtor Concreto):** Implementação que de fato constrói e monta as partes do produto, mantendo o rastro da representação criada e definindo a interface para a recuperação do produto final.
* **Director (Diretor - Opcional):** Classe responsável por gerenciar a ordem de execução dos passos de construção, definindo receitas de montagem predefinidas.

### 1.3. Variações Comuns
* **Interface Fluente (Fluent Interface):** Os métodos do Builder retornam a própria instância do construtor (`return this`), permitindo o encadeamento de chamadas de métodos de forma contínua e expressiva.
* **Builder sem Diretor:** O próprio cliente atua como diretor, escolhendo de forma dinâmica e personalizada quais passos invocar diretamente no código.

### 1.5. Como Funciona
* O `Client` cria uma instância do `ConcreteBuilder`.
* O `Client` chama os métodos de configuração passo a passo (ex: `setId`, `setNome`), moldando as características do objeto em construção.
* Para adicionar componentes complexos ou coleções, o `Builder` pode delegar a inserção a métodos internos do próprio produto (ex: `adicionarModulo`).
* O `Client` finaliza o processo invocando o método `build()`.
* O método `build()` retorna o produto completamente configurado e reinicia o estado interno do construtor através do método `reset()`, preparando-o para uma nova criação.

### 1.6. Benefícios
* Permite variar a representação interna de um produto de forma isolada.
* Encapsula o código de construção e montagem, separando-o da lógica de negócio do produto.
* Melhora drasticamente a legibilidade do código de criação através do encadeamento de métodos.
* Facilita a criação de objetos complexos com estruturas compostas ou listas dinâmicas.

### 1.7. Desvantagens
* Aumenta a complexity geral do código pela necessidade de criar uma classe Builder para cada produto complexo.
* Pode gerar sobrecarga de memória temporária durante o processo passo a passo de instanciação.

# 2. Aplicação do Padrão Builder no Projeto "ConhecendoIA"
No projeto ConhecendoIA, o padrão Builder é aplicado no sistema de Customização de Conteúdos por meio da classe `TrilhaAprendizagemBuilder`, permitindo que professores, administradores ou o próprio algoritmo de recomendação montem estruturas pedagógicas personalizadas (`TrilhaAprendizagem`) com diferentes quantidades de módulos, níveis de dificuldade e objetivos específicos.

## 2.1. Contexto do Problema
Uma trilha de aprendizagem dentro da plataforma "ConhecendoIA" é uma estrutura rica. Ela possui metadados (ID, nome, objetivo), classificação de nivelamento e uma coleção dinâmica de módulos de conteúdo que se conectam com o Fórum e a IDE Python.

Criar essas trilhas diretamente por meio de um operador `new` tradicional exigiria um construtor massivo e confuso. Além disso, uma trilha para um usuário iniciante pode não conter módulos avançados de redes neurais, enquanto uma trilha prática precisa de uma carga massiva de laboratórios de código. Sem o Builder, o código de criação ficaria repleto de arranjos manuais de arrays, tornando a manutenção propensa a falhas de consistência de dados.

## 2.2. Solução com TrilhaAprendizagemBuilder como Builder
A classe `TrilhaAprendizagemBuilder` encapsula a instanciação da `TrilhaAprendizagem`. Através de uma interface fluente, é possível encadear propriedades de forma clara e dinâmica.

O builder delega adequadamente a adição de elementos compostos ao método `adicionarModulo` contido na própria entidade do produto, respeitando o modelo conceitual do diagrama de classes e mantendo a integridade do objeto durante o ciclo de montagem.

```javascript
// Produto
class TrilhaAprendizagem {
  constructor() {
    this.id = null;
    this.nome = "";
    this.objetivo = "";
    this.nivel = "";
    this.modulos = [];
  }

  // Método do diagrama — pertence ao produto, não ao builder
  adicionarModulo(m) {
    this.modulos.push(m);
  }

  // Método do diagrama
  recomendarParaUsuario(u) {
    return this.nivel === u.nivel;
  }
}

// Builder
class TrilhaAprendizagemBuilder {
  constructor() {
    this.reset();
  }

  reset() {
    this.trilha = new TrilhaAprendizagem();
    return this;
  }

  setId(id) {
    this.trilha.id = id;
    return this;
  }

  setNome(nome) {
    this.trilha.nome = nome;
    return this;
  }

  setObjetivo(objetivo) {
    this.trilha.objetivo = objetivo;
    return this;
  }

  setNivel(nivel) {
    this.trilha.nivel = nivel;
    return this;
  }

  // Builder delega ao método do produto
  comModulo(modulo) {
    this.trilha.adicionarModulo(modulo);
    return this;
  }

  build() {
    const resultado = this.trilha;
    this.reset();
    return resultado;
  }
}
```
