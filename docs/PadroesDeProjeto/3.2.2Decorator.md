# 3.2.2 Decorator

## 1. Introdução ao Padrão Decorator

O padrão de projeto **Decorator** é um padrão estrutural que permite adicionar funcionalidades a objetos de forma dinâmica, sem modificar sua estrutura original (Gamma et al., 1995). Ele fornece uma alternativa flexível à herança para estender comportamentos em tempo de execução.

Em vez de alterar diretamente o código do handler ou da função, o Decorator **envolve** o objeto-alvo com um novo objeto que adiciona o comportamento desejado antes (ou após) de delegar a chamada ao componente original.

---

### 1.1. Problema que o Decorator Resolve

Durante o desenvolvimento de plataformas web, é comum que comportamentos transversais — como autenticação, logging e controle de taxa — precisem ser aplicados em múltiplos endpoints de forma modular e reutilizável, sem poluir a lógica de negócio.

O padrão Decorator resolve os seguintes problemas (Refactoring Guru, [s.d.]):

- **Adição Dinâmica de Comportamento:** Permite modificar o comportamento de handlers sem alterar seu código-fonte.
- **Alta Reutilização:** Os comportamentos adicionais são compostos e aplicados a diferentes rotas de forma reutilizável.
- **Separação de Responsabilidades:** A lógica de negócio e a lógica auxiliar (autenticação, log, rate limit) ficam desacopladas.
- **Composição Flexível:** Múltiplos decorators podem ser encadeados em qualquer ordem para criar combinações de comportamentos.

---

### 1.2. Estrutura e Participantes

Os principais participantes do padrão Decorator neste projeto são:

| Participante | Descrição | No Código |
|---|---|---|
| **Componente** | Interface/assinatura que define as operações decoráveis | Handlers Express `(req, res, next)` |
| **Componente Concreto** | Implementação original da funcionalidade | `executarCodigoIA`, `criarTopico` |
| **Decorator Base** | Mantém referência ao componente e implementa a mesma interface | `RequestDecorator` |
| **Decoradores Concretos** | Adicionam comportamentos ao componente concreto | `AuthDecorator`, `LoggerDecorator`, `RateLimitDecorator`, `GamificationDecorator`, `ModerationDecorator` |
| **Factory** | Centraliza e simplifica a composição dos decorators | `DecoratorFactory` |

### 1.4. Como Funciona

1. O cliente chama o middleware da rota decorada.
2. O **RateLimitDecorator** intercepta primeiro: verifica se o usuário atingiu o limite de requisições na janela de tempo.
3. Se aprovado, o **AuthDecorator** verifica se o token JWT é válido e injeta os dados do usuário em `req.user`.
4. Se autenticado, o **LoggerDecorator** registra início, rota e usuário; configura a captura do status de resposta.
5. O handler original é executado com a lógica de negócio.
6. O **GamificationDecorator** (quando presente) intercepta a resposta: se bem-sucedida (status 2xx), concede XP ao usuário e injeta `_xpGanho` no corpo da resposta.
7. O **LoggerDecorator** registra o tempo de execução e status da resposta.
8. A resposta final é entregue ao cliente.

---

### 1.5. Benefícios

- Modularidade e reutilização entre diferentes rotas
- Separação clara entre lógica principal e lógica transversal
- Composição flexível e encadeável via `DecoratorFactory`
- Fácil extensão: novos comportamentos não alteram handlers existentes

### 1.6. Desvantagens

- Pode aumentar a complexidade ao encadear muitos decorators
- Depuração pode ser mais difícil (stack trace com múltiplos wrappers)
- A ordem de aplicação dos decorators impacta o comportamento e exige atenção

## 2. Aplicação do Padrão Decorator no Projeto "ConhecendoIA"

No projeto ConhecendoIA, usamos decorators para aplicar camadas de **autenticação**, **logging**, **rate limiting**, **gamificação** e **moderação** de forma dinâmica e reutilizável sobre os handlers das rotas Express.

**Localização:** `projeto/src/decorators/RequestDecorator.js`

---

### 2.1. Contexto do Problema

A plataforma ConhecendoIA possui diversas funcionalidades que exigem proteção e rastreabilidade:

- A **IDE Python com IA** executa código dos usuários via API de IA — precisa de autenticação e controle de uso para evitar abuso da API.
- O **Fórum** exige que apenas usuários autenticados criem tópicos e comentários; ações de moderação (fixar tópico, banir usuário) são restritas a moderadores e admins.
- O **Dashboard** precisa registrar acessos para métricas de uso.
- O **Sistema de Gamificação** (badges, ranking, quizzes) precisa conceder XP ao usuário após ações bem-sucedidas, sem poluir a lógica de cada endpoint.

Aplicar autenticação, logging e gamificação diretamente em cada handler espalharia código duplicado e dificultaria a manutenção. O Decorator centraliza esses comportamentos.

---

### 2.2. Os Decorators Implementados

#### `AuthDecorator` — Verificação de Autenticação JWT

Intercepta a requisição e valida o token Bearer antes de executar o handler.

```javascript
class AuthDecorator extends RequestDecorator {
  async execute(req, res, next) {
    const authHeader = req.headers["authorization"];

    if (!authHeader || !authHeader.startsWith("Bearer ")) {
      return res.status(401).json({ error: "Autenticação necessária. Token não fornecido." });
    }

    const token = authHeader.split(" ")[1];

    try {
      const decoded = this._verifyToken(token);
      req.user = decoded;
      return super.execute(req, res, next);  // delega ao próximo decorator/handler
    } catch (err) {
      return res.status(401).json({ error: "Token inválido ou expirado.", details: err.message });
    }
  }
}
```

---

#### `LoggerDecorator` — Registro de Requisições

Registra método, rota, usuário, status e tempo de execução de forma não-intrusiva.

```javascript
class LoggerDecorator extends RequestDecorator {
  async execute(req, res, next) {
    const inicio = Date.now();
    const userId = req.user?.id ?? "anônimo";
    const label = this._context ? `[${this._context}]` : "[ConhecendoIA]";

    this._logger(`${label} → ${req.method} ${req.originalUrl} | usuário: ${userId}`);

    const originalJson = res.json.bind(res);
    res.json = (body) => {
      const duracao = Date.now() - inicio;
      this._logger(`${label} ← status: ${res.statusCode} | ${duracao}ms`);
      return originalJson(body);
    };

    return super.execute(req, res, next);
  }
}
```

---

#### `RateLimitDecorator` — Controle de Taxa para IA

Limita quantas vezes um usuário pode acionar um endpoint em uma janela de tempo, protegendo a API de IA contra uso excessivo.

```javascript
class RateLimitDecorator extends RequestDecorator {
  async execute(req, res, next) {
    const chave = req.user?.id ?? req.ip;
    const agora = Date.now();
    const registro = this._registros.get(chave);

    if (!registro || agora > registro.resetAt) {
      this._registros.set(chave, { count: 1, resetAt: agora + this._janelaMs });
    } else if (registro.count < this._limite) {
      registro.count++;
    } else {
      const resetEm = Math.ceil((registro.resetAt - agora) / 1000);
      return res.status(429).json({ error: this._mensagem, resetEm: `${resetEm}s` });
    }

    return super.execute(req, res, next);
  }
}
```

---

#### `GamificationDecorator` — Concessão de XP e Badges

Concede XP ao usuário após a execução bem-sucedida de uma ação (criar tópico, comentar, completar quiz, executar código na IDE), alimentando o sistema de ranking e conquistas do ConhecendoIA sem poluir a lógica de cada endpoint.

```javascript
class GamificationDecorator extends RequestDecorator {
  async execute(req, res, next) {
    const originalJson = res.json.bind(res);
    res.json = async (body) => {
      if (res.statusCode >= 200 && res.statusCode < 300 && req.user?.id) {
        const userId = req.user.id;
        const xpGanho = this._xp;

        if (this._xpService) {
          await this._xpService.adicionarXP(userId, xpGanho, this._acao);
        } else {
          console.log(`[Gamification] +${xpGanho} XP → usuário ${userId} | ação: ${this._acao}`);
        }

        // Retorna XP ganho no corpo da resposta para o frontend
        if (typeof body === "object" && body !== null) {
          body._xpGanho = xpGanho;
        }
      }
      return originalJson(body);
    };

    return super.execute(req, res, next);
  }
}
```

**Parâmetros de configuração:**

| Parâmetro | Tipo | Padrão | Descrição |
|---|---|---|---|
| `xp` | `number` | `10` | XP concedido ao completar a ação com sucesso |
| `acao` | `string` | `'acao'` | Nome da ação para o log de conquistas |
| `xpService` | `Function\|null` | `null` | Serviço responsável por persistir o XP no banco |

---

#### `ModerationDecorator` — Controle de Acesso por Papel

Verifica se o usuário possui o papel (`role`) necessário para executar ações restritas no Fórum, como fixar tópicos, banir usuários, remover conteúdo ou gerenciar categorias. Deve ser aplicado **após** o `AuthDecorator`, pois depende de `req.user`.

```javascript
class ModerationDecorator extends RequestDecorator {
  async execute(req, res, next) {
    const user = req.user;

    if (!user) {
      return res.status(401).json({ error: "Usuário não autenticado." });
    }

    const papelUsuario = user.papel ?? user.role ?? "";
    const temPermissao = this._papeis.includes(papelUsuario);

    if (!temPermissao) {
      return res.status(403).json({
        error: this._mensagem,
        papelAtual: papelUsuario,
        papelNecessario: this._papeis,
      });
    }

    return super.execute(req, res, next);
  }
}
```

**Parâmetros de configuração:**

| Parâmetro | Tipo | Padrão | Descrição |
|---|---|---|---|
| `papeis` | `string[]` | `['moderador']` | Lista de papéis com permissão de acesso |
| `mensagem` | `string` | Mensagem padrão | Mensagem de erro customizável retornada ao cliente |

---

### 2.3. A `DecoratorFactory`

A `DecoratorFactory` centraliza a composição dos decorators, expondo métodos estáticos que encadeiam os comportamentos de forma legível e segura.

| Método | Cadeia de Decorators | Caso de Uso |
|---|---|---|
| `comAuth(handler, verifyToken)` | Auth → Handler | Rotas simples com autenticação |
| `comLogger(handler, options)` | Logger → Handler | Monitoramento de rotas públicas |
| `comRateLimit(handler, options)` | RateLimit → Handler | Endpoints com limite de uso |
| `comGamificacao(handler, options)` | Gamification → Handler | Ações que rendem XP sem autenticação prévia encadeada |
| `comModeracao(handler, options)` | Moderation → Handler | Ações restritas (após Auth já aplicado) |
| `comTudo(handler, opcoes)` | RateLimit → Auth → Logger → Gamification → Handler | Endpoints de IA com proteção completa |
| `comModeradorCompleto(handler, opcoes)` | Auth → Moderation → Logger → Handler | Rotas administrativas do Fórum |

---

### 2.4. Exemplo de Uso nas Rotas

#### Rota da IDE Python com IA — proteção completa

```javascript
// projeto/src/routes/iaRoutes.js
const { DecoratorFactory } = require('../decorators/RequestDecorator');
const jwt = require('jsonwebtoken');

const verifyToken = (token) => jwt.verify(token, process.env.JWT_SECRET);

// Handler original — apenas lógica de negócio
async function executarCodigoIA(req, res) {
  const { codigo } = req.body;
  // lógica de execução na IA...
  return res.json({ resultado: '...' });
}

// Composição completa: RateLimit → Auth → Logger → Gamification → Handler
const executarDecorado = DecoratorFactory.comTudo(executarCodigoIA, {
  verifyToken,
  logger:      { context: 'IDE-Python' },
  rateLimit:   { limite: 5, janelaMs: 60_000 },  // 5 execuções/min por usuário
  gamificacao: { xp: 20, acao: 'executar-codigo' },
});

router.post('/executar', executarDecorado.toMiddleware());
```

#### Rota de moderação do Fórum

```javascript
// Handler original — lógica de banimento
async function banirUsuario(req, res) {
  const { userId } = req.params;
  // lógica de banimento...
  return res.json({ sucesso: true });
}

// Composição para moderadores: Auth → Moderation → Logger → Handler
const banirDecorado = DecoratorFactory.comModeradorCompleto(banirUsuario, {
  verifyToken,
  papeis: ['moderador', 'admin'],
  logger: { context: 'Forum-Moderacao' },
});

router.delete('/forum/usuario/:userId', banirDecorado.toMiddleware());
```

#### Rota de criação de tópico com gamificação

```javascript
async function criarTopico(req, res) {
  // lógica do fórum...
  return res.json({ topico: '...' });
}

// Auth → Logger → Gamification → Handler (composição manual)
let decorado = new GamificationDecorator(criarTopico, { xp: 15, acao: 'criar-topico' });
decorado = new LoggerDecorator(decorado.toMiddleware(), { context: 'Forum' });
decorado = new AuthDecorator(decorado.toMiddleware(), verifyToken);

router.post('/forum/topico', decorado.toMiddleware());
```

---

### 2.5. Vantagens no Projeto

- **Reutilização:** Os decorators são aplicados a qualquer rota do Fórum, IDE ou Dashboard sem duplicar código.
- **Separação de Responsabilidades:** Handlers contêm apenas lógica de negócio; comportamentos transversais ficam nos decorators.
- **Manutenção Simples:** Alterar a lógica de autenticação, por exemplo, afeta apenas o `AuthDecorator`.
- **Composição Flexível:** A `DecoratorFactory` permite combinar decorators conforme a necessidade de cada rota.
- **Extensibilidade:** A adição dos decorators `GamificationDecorator` e `ModerationDecorator` não exigiu nenhuma alteração nos handlers existentes.
