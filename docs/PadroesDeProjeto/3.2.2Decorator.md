# 3.2.2 Decorator

## 1. Introdução ao Padrão Decorator
O padrão de projeto Decorator é um padrão estrutural que permite adicionar novas funcionalidades a objetos de forma dinâmica, sem modificar sua estrutura original. Ele fornece uma alternativa flexível à herança para estender comportamentos de objetos em tempo de execução [[2]](#ref2).

Em vez de alterar diretamente o código de uma classe base, o Decorator envolve o objeto-alvo com um novo objeto (wrapper) que adiciona o comportamento desejado.

### 1.1. Problema que o Decorator Resolve
Durante o desenvolvimento de sistemas complexos, frequentemente surge a necessidade de adicionar funcionalidades a um objeto específico de forma modular e reutilizável — por exemplo, medição de performance, verificação de segurança, logging, etc. O uso excessivo de herança para criar combinações desses comportamentos pode levar a uma explosão de subclasses.

O padrão Decorator resolve os seguintes problemas [[1]](#ref1):

* **Adição Dinâmica de Comportamento:** Permite estender o comportamento de métodos ou funções em tempo de execução.
* **Alta Reutilização:** Evita a criação de dezenas de subclasses combinando diferentes funcionalidades. Comportamentos adicionais podem ser aplicados em diferentes componentes.
* **Separação de Responsabilidades:** A lógica principal e as lógicas auxiliares (como medição de métricas ou segurança) ficam separadas, o que torna o código mais limpo [[3]](#ref3).

### 1.2. Estrutura e Participantes
Os principais participantes do padrão Decorator são:

* **Componente:** A interface comum que define as operações que podem ser decoradas. No nosso contexto: A interface de execução de código (`CodeExecutor`).
* **Componente Concreto:** Implementação original da funcionalidade. No nosso contexto: O executor de código Python nativo (`PythonCodeExecutor`).
* **Decorator (Base):** Abstração que mantém uma referência ao componente e define a interface compatível com o componente. No nosso contexto: A classe base `ExecutorDecorator`.
* **Decorador Concreto:** Adiciona funcionalidades ao componente concreto. No nosso contexto: As classes `MetricsDecorator` e `SecuritySandboxDecorator`.

### 1.4. Como Funciona
1. O código chama o componente decorado.
2. O decorador intercepta a chamada e pode adicionar seu comportamento extra (antes ou depois).
3. O decorador decide se deve ou não permitir que o componente original (ou o próximo decorador) seja executado.
4. Caso permitido, o comportamento original é executado.
5. O resultado da execução é retornado em cadeia até chegar ao cliente.

## 2. Aplicação do Padrão Decorator no Projeto "ConhecendoIA"

No projeto **ConhecendoIA**, utilizamos decoradores para adicionar funcionalidades dinâmicas e de segurança ao sistema de **IDE Python**, onde os alunos executam scripts de Inteligência Artificial e Machine Learning diretamente pelo navegador. 

**Localização:** `frontend/src/services/ide/Executors.js`

### 2.1. Classes Decoradoras
A classe base `PythonCodeExecutor` executa o código do aluno. Para fins de ensino e segurança, adicionamos os decoradores `MetricsDecorator` (para avaliar performance do modelo de IA) e `SecuritySandboxDecorator` (para impedir acesso indevido do script à rede ou ao sistema).

```javascript
// Interface / Classe Base
export class CodeExecutor {
  async execute(code) { throw new Error("Não implementado"); }
}

// Componente Concreto (O executor real)
export class PythonCodeExecutor extends CodeExecutor {
  async execute(code) {
    console.log("[IDE] Executando código Python nativo do aluno...");
    
    // Simulando o tempo de execução de um modelo de ML (500ms)
    await new Promise(resolve => setTimeout(resolve, 500));
    
    return { output: "Modelo de ML treinado com sucesso!", error: null };
  }
}

// Decorator Base
export class ExecutorDecorator extends CodeExecutor {
  constructor(executor) {
    super();
    this.wrapper = executor; // Guarda a referência do objeto decorado
  }

  async execute(code) {
    return await this.wrapper.execute(code);
  }
}

// Decorator Concreto 1: Verificação de Segurança (Sandbox)
export class SecuritySandboxDecorator extends ExecutorDecorator {
  async execute(code) {
    console.log("[Sandbox] Verificando código em busca de ameaças...");
    
    if (code.includes("import os") || code.includes("subprocess")) {
      return { 
        output: null, 
        error: "ERRO DE SEGURANÇA: Acesso ao sistema negado pelo Sandbox." 
      };
    }
    
    // Se estiver seguro, repassa para o próximo nível
    return await super.execute(code); 
  }
}

// Decorator Concreto 2: Métricas de Performance
export class MetricsDecorator extends ExecutorDecorator {
  async execute(code) {
    console.log("[Métricas] Iniciando cronômetro...");
    const start = performance.now();
    
    // Executa a cadeia (pode ser o Sandbox ou o Executor real)
    const result = await super.execute(code);
    
    const end = performance.now();
    result.executionTimeMs = (end - start).toFixed(2);
    
    console.log(`[Métricas] Execução finalizada em ${result.executionTimeMs}ms`);
    return result;
  }
}
```

### 2.2. Exemplo de Uso do Decorator
No controlador da API, as camadas podem ser empilhadas dependendo do que for necessário para a atividade.

```javascript
async function runStudentCode() {
    const studentCode = "import numpy as np\nprint('Treinando Rede Neural...')";
    
    // Montagem dinâmica das responsabilidades
    let executor = new PythonCodeExecutor();
    executor = new SecuritySandboxDecorator(executor); // Adiciona segurança
    executor = new MetricsDecorator(executor);         // Adiciona medição de tempo
    
    const result = await executor.execute(studentCode);
    console.log(result);
}
```

### 2.3. Vantagens no Projeto
* **Modularidade:** É muito fácil criar um novo decorador, como `TimeoutDecorator` (para interromper execuções longas), sem mexer na lógica atual.
* **Composição Dinâmica:** Se a execução for por um professor, podemos não usar o `SecuritySandboxDecorator`. Se for um aluno, usamos todos os decoradores de restrição.
* **Separação Clara:** A execução real do Python está em um lugar, a segurança em outro, e as métricas em outro.

## 3. Benefícios
* Extensibilidade e modularidade do código [[3]](#ref3).
* Reutilização de código.
* Separação clara entre a lógica principal e as lógicas adicionais [[1]](#ref1).
* Prevenção do problema de explosão de subclasses em sistemas complexos.

## 4. Desvantagens
* Pode aumentar a complexidade ao instanciar os objetos se houver muitos decoradores aninhados (a ordem de montagem importa).
* A depuração pode ser mais difícil devido ao stack trace passar por múltiplos wrappers.
* Resulta em um grande número de pequenas classes no sistema.
